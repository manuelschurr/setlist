## Q1. The `.fitnotes` backup format

### Container

The backup is a plain, unencrypted SQLite file, named `FitNotes_Backup.fitnotes` or with a timestamp in the name ([fitnotesapp.com/settings](https://www.fitnotesapp.com/settings/), [S5]). `PRAGMA user_version` is 22 on current backups, and the cakerug importer refuses any other version (`EXPECTED_USER_VERSION = 22` in `src/server/db.server.ts` of [cakerug/fitnotes_web](https://github.com/cakerug/fitnotes_web), [S2]). Automatic Google Drive backups can show up as `.zip` files: a user attached `FitNotes_Automatic_Backup_2024_04_12_17_31_27.zip` to [workout-tracker issue #55](https://github.com/jovandeginste/workout-tracker/issues/55). The importer should unzip first if it gets a zip (inferred).

### Tables that matter (exact DDL from [S1])

```sql
CREATE TABLE Category(_id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL, colour INTEGER NOT NULL DEFAULT 0, sort_order INTEGER NOT NULL DEFAULT 0);
CREATE TABLE exercise(_id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL, category_id INTEGER NOT NULL, exercise_type_id INTEGER NOT NULL DEFAULT 0, notes TEXT, weight_increment INTEGER, default_graph_id INTEGER, default_rest_time INTEGER, weight_unit_id INTEGER NOT NULL DEFAULT 0, is_favourite INTEGER NOT NULL DEFAULT 0);
CREATE TABLE training_log (_id INTEGER PRIMARY KEY AUTOINCREMENT, exercise_id INTEGER NOT NULL, date DATE NOT NULL, metric_weight INTEGER NOT NULL, reps INTEGER NOT NULL, unit INTEGER NOT NULL DEFAULT 0, routine_section_exercise_set_id INTEGER NOT NULL DEFAULT 0, timer_auto_start INTEGER NOT NULL DEFAULT 0, is_personal_record INTEGER NOT NULL DEFAULT 0, is_personal_record_first INTEGER NOT NULL DEFAULT 0, is_complete INTEGER NOT NULL DEFAULT 0, is_pending_update INTEGER NOT NULL DEFAULT 0, distance INTEGER NOT NULL DEFAULT 0, duration_seconds INTEGER NOT NULL DEFAULT 0);
CREATE TABLE Routine(_id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL, notes TEXT);
CREATE TABLE RoutineSection(_id INTEGER PRIMARY KEY AUTOINCREMENT, routine_id INTEGER NOT NULL, name TEXT NOT NULL, sort_order INTEGER NOT NULL DEFAULT '0');
CREATE TABLE RoutineSectionExercise(_id INTEGER PRIMARY KEY AUTOINCREMENT, routine_section_id INTEGER NOT NULL, exercise_id INTEGER NOT NULL, sort_order INTEGER NOT NULL DEFAULT 0, populate_sets_type INTEGER NOT NULL DEFAULT 0);
CREATE TABLE RoutineSectionExerciseSet(_id INTEGER PRIMARY KEY AUTOINCREMENT, routine_section_exercise_id INTEGER NOT NULL, metric_weight INTEGER NOT NULL, reps INTEGER NOT NULL, sort_order INTEGER NOT NULL DEFAULT 0, distance INTEGER NOT NULL DEFAULT 0, duration_seconds INTEGER NOT NULL DEFAULT 0, unit INTEGER NOT NULL DEFAULT 0);
CREATE TABLE Comment (_id INTEGER PRIMARY KEY AUTOINCREMENT, date DATE NOT NULL, owner_type_id INTEGER NOT NULL, owner_id INTEGER NOT NULL, comment TEXT NOT NULL);
CREATE TABLE WorkoutComment (_id INTEGER PRIMARY KEY AUTOINCREMENT, date TEXT NOT NULL, comment TEXT NOT NULL);
CREATE TABLE WorkoutGroup (_id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL, date TEXT NOT NULL, colour INTEGER NOT NULL, routine_section_id INTEGER, auto_jump_enabled INTEGER NOT NULL DEFAULT 1, rest_timer_auto_start_enabled INTEGER NOT NULL DEFAULT 0);
CREATE TABLE WorkoutGroupExercise(_id INTEGER PRIMARY KEY AUTOINCREMENT, exercise_id INTEGER NOT NULL, date TEXT NOT NULL, routine_section_id INTEGER NOT NULL, workout_group_id INTEGER NOT NULL);
CREATE TABLE WorkoutTime (_id INTEGER PRIMARY KEY AUTOINCREMENT, workout_date TEXT NOT NULL, start_date_time TEXT NOT NULL, end_date_time TEXT NOT NULL);
CREATE TABLE BodyWeight (_id INTEGER PRIMARY KEY AUTOINCREMENT, date TEXT NOT NULL, body_weight_metric REAL NOT NULL, body_fat REAL NOT NULL, comments TEXT);
CREATE TABLE Barbell (_id INTEGER PRIMARY KEY AUTOINCREMENT, weight REAL NOT NULL, unit INTEGER NOT NULL DEFAULT 0, exercise_id INTEGER NOT NULL DEFAULT 0);
CREATE TABLE Plate (_id INTEGER PRIMARY KEY AUTOINCREMENT, weight REAL NOT NULL, unit INTEGER NOT NULL DEFAULT 0, count INTEGER NOT NULL DEFAULT 0, enabled INTEGER NOT NULL DEFAULT 0, colour INTEGER NOT NULL DEFAULT 0, width_ratio REAL NOT NULL DEFAULT 1, height_ratio REAL NOT NULL DEFAULT 1);
```

Also present but less relevant: `Goal`, `ExerciseGraphFavourite`, `RepMaxGridFavourite`, `Measurement`, `MeasurementRecord`, `MeasurementUnit`, a single-row `settings` table with about 44 columns, and `android_metadata` [S1].

### Value conventions

- **Date**: text `YYYY-MM-DD` in `training_log.date` [S5]. The column is declared `DATE`, but SQLite stores it as text.
- **Weight**: `metric_weight` holds kilograms as a real number, even though the column is declared `INTEGER`. SQLite type affinity keeps the decimals (inferred from the `double metricWeight` field in [TrainingLog.java](https://github.com/stoyanov-x/fitnotes-research/blob/main/decompiled/sources/com/github/jamesgay/fitnotes/model/TrainingLog.java) and from [S2]). Pound values are converted with the factor 2.20462 ([G0.java](https://github.com/stoyanov-x/fitnotes-research/blob/main/decompiled/sources/com/github/jamesgay/fitnotes/util/G0.java)), so a lb-logged 45 is stored as about 20.4117 kg. Round on display.
- **Display unit per exercise**: `exercise.weight_unit_id` is 0 = Default (follow the global setting), 1 = Metric (kg), 2 = Imperial (lbs) ([ExerciseWeightUnit.java](https://github.com/stoyanov-x/fitnotes-research/blob/main/decompiled/sources/com/github/jamesgay/fitnotes/model/ExerciseWeightUnit.java)). The global unit is `settings.metric`. FlexNotes reads it as 0 = imperial and 1 = metric [S4].
- **`training_log.unit` is the distance unit**, not the weight unit. The Java setter annotated `@Y.a("unit")` writes `distanceUnitId` (TrainingLog.java). [DistanceUnit.java](https://github.com/stoyanov-x/fitnotes-research/blob/main/decompiled/sources/com/github/jamesgay/fitnotes/model/DistanceUnit.java) defines METRES=2, KILOMETRES=3, FEET=4, MILES=5, and unknown values fall back to metres. `distance` is stored in that unit, not converted to metres, because the CSV exporter writes the raw `distance` next to that unit's short string ([Z0/c.java](https://github.com/stoyanov-x/fitnotes-research/blob/main/decompiled/sources/Z0/c.java)). FlexNotes instead guesses 0 km, 1 mi, 2 m, 3 yd and confirms only metres=2 [S4]. Trust the decompiled enum.
- **Duration**: `duration_seconds` is an integer number of seconds [S1].
- **Exercise types** (`exercise_type_id`, from [ExerciseType.java](https://github.com/stoyanov-x/fitnotes-research/blob/main/decompiled/sources/com/github/jamesgay/fitnotes/model/ExerciseType.java)): 0 weight+reps, 1 distance+time, 2 weight+distance, 3 weight+time, 4 reps+distance, 5 reps+time, 6 weight only, 7 reps only, 8 distance only, 9 time only. [S2] says a Plank used id 3 and calls 3 "Time-only". That conflicts with the enum, and the user may simply have logged the plank as weight+time. Unused fields are stored as 0.
- **Set order within a day**: by `_id` ascending. FitNotes queries use `ORDER BY t.date DESC, t._id ASC` ([X/J0.java](https://github.com/stoyanov-x/fitnotes-research/blob/main/decompiled/sources/X/J0.java)), and both importers read `ORDER BY t.date, t._id` [S4].
- **Exercise order within a day**: there is no ordering table. FitNotes ranks the exercises in a day by the smallest set `_id`, using `SELECT MIN(_id) AS min_id FROM training_log GROUP BY date, exercise_id ORDER BY min_id` (J0.java). When you drag an exercise or set into a new place, FitNotes deletes every `training_log` row for that date. It then re-inserts them in the new order and points each `Comment.owner_id` (owner_type_id = 1) at the new `_id` (method `K2` in J0.java, called from the drawer drag handler in [TrainingLogActivity.java](https://github.com/stoyanov-x/fitnotes-research/blob/main/decompiled/sources/com/github/jamesgay/fitnotes/feature/exercise/workout/TrainingLogActivity.java)). This means set ids are not stable across reorders.
- **Comments**: `Comment.owner_type_id` 1 = a training_log set and 2 = a workout ([Comment.java](https://github.com/stoyanov-x/fitnotes-research/blob/main/decompiled/sources/com/github/jamesgay/fitnotes/model/Comment.java)). The workout note shown on the home screen lives in `WorkoutComment(date, comment)`, and FlexNotes reads it from there [S4]. A set can have more than one comment, which is why FlexNotes joins them with `group_concat(cm.comment, ' / ')` [S4].
- **Done flag**: `training_log.is_complete` is 0 or 1 and is used only when the "Mark Sets Complete" setting is on ([fitnotesapp.com/settings](https://www.fitnotesapp.com/settings/)). The code that toggles it also clears `is_pending_update` (J0.java line ~1094). Inferred: `is_pending_update` = 1 marks a placeholder set from a routine or copy whose values have not been filled in yet.
- **PR flags**: `is_personal_record` and `is_personal_record_first` [S1]. Only sets that are current records keep the trophy: on 25.1, logging 120x12 removed the flag from 120x10 and 100x10 [S2]. Settings has a "Calculate Personal Records" action to recompute them ([settings page](https://www.fitnotesapp.com/settings/)), so recompute on import rather than trusting the flags.
- **Supersets in the log**: `WorkoutGroup` (one row per group per date, with colour and the `auto_jump_enabled` and `rest_timer_auto_start_enabled` flags) plus `WorkoutGroupExercise(exercise_id, date, workout_group_id)` [S1]. In routines, the same tables are keyed by `routine_section_id` (inferred from the columns and [S2]).
- **Routines**: Routine > RoutineSection (a "Day", sorted by `sort_order`) > RoutineSectionExercise (`sort_order`, `populate_sets_type`: 0 NONE, 1 PREDEFINED_SETS, 2 COPY_PREVIOUS_WORKOUT, from [X/C0250e0.java](https://github.com/stoyanov-x/fitnotes-research/blob/main/decompiled/sources/X/C0250e0.java)) > RoutineSectionExerciseSet. A predefined set field left blank means "copy from the previous workout" ([routines guide](https://www.fitnotesapp.com/routines/)). Inferred: blank is stored as 0.
- **Estimated 1RM**: Brzycki, `w * 36 / (37 - reps)`, which [S2] checked against the FitNotes glossary example.
- **Category colour**: a signed ARGB integer [S2].

### Fallback: CSV export

Current Android header, read from real exports [S2]: `Date,Exercise,Category,Weight,Weight Unit,Reps,Distance,Distance Unit,Time,Comment`. `Weight Unit` is `kgs` or `lbs` [S2]. `Time` is `H:MM:SS`, and `Comment` is optional ([stoyanov-x export doc](https://github.com/stoyanov-x/fitnotes-research/blob/main/docs/research/FITNOTES_EXPORT_FORMAT.md)). Older exports used `Date,Exercise,Category,Weight (lbs),Reps,Distance,Distance Unit,Time` [S2]. One importer reports locale-formatted dates such as `23/12/2025` ([TraceApps](https://traceapps.github.io/docs/lifttrace/import/)), so parse defensively. The CSV has no routines, set order beyond row order, supersets, completion flags or workout comments, and FitNotes cannot restore from it ([settings](https://www.fitnotesapp.com/settings/)). Do not confuse it with the 11-column iOS "FitNotes 2" format, `...Weight (kg),Weight (lbs),...,Notes,Kind`, from a different developer ([getfitnotes.com](https://www.getfitnotes.com/docs/migrate-from-other-apps.html)).

Other code that reads `.fitnotes` files: BetaRavener's routine copier ([FitNotes-Import](https://github.com/BetaRavener/FitNotes-Import)) and an MCP server ([fitnotes_mcp](https://github.com/makkoncept/fitnotes_mcp)). Badger and LiftJot import the backup file ([badger.fit](https://badger.fit/guides/switching/), [liftjot.com](https://liftjot.com/import)). I found no FitNotes importer in Liftosaur, which imports Hevy CSV only ([liftosaur.com](https://www.liftosaur.com/features/import-export)). GitHub code search of the Flexify, LiftLog, Massive and wger repos returned no "fitnotes" hits.

## Q2. FitNotes itself

**Flow.** The Home Screen shows one day's workout. You swipe or tap arrows to change day. An empty day offers "Start New Workout" and "Copy Previous Workout" ([home_screen](https://www.fitnotesapp.com/home_screen/)). Picking an exercise opens the **Training Screen**, which shows one exercise at a time with TRACK / HISTORY / GRAPH tabs. TRACK has weight and reps fields with +/- steppers, Save/Clear buttons (Update/Delete when a set is selected) and the day's set list. The fields pre-fill with "the first set from the last workout" ([workout_tracking](https://www.fitnotesapp.com/workout_tracking/)). Each identical set is a separate row. To get to another exercise you open the Navigation Panel drawer, which lists the exercises with their set counts ([workout_tracking](https://www.fitnotesapp.com/workout_tracking/)). This is pain point 1.

**Copy workout.** You pick a date from the calendar, tick the exercises and sets, optionally edit them, then Copy ([home_screen](https://www.fitnotesapp.com/home_screen/)). To change the copied values you open each exercise, tap a set and press Update, one set at a time ([routines](https://www.fitnotesapp.com/routines/)). This is pain point 2. Bulk editing exists only in Training History ("Edit Sets" for a past date) ([progress_tracking](https://www.fitnotesapp.com/progress_tracking/)).

**Mark Sets Complete.** An optional checkbox on each set. "Once you have completed all of the sets for an exercise you will automatically be prompted to jump to the next exercise" ([workout_tracking](https://www.fitnotesapp.com/workout_tracking/)). This is pain point 3. "Auto-Select Next Set" selects the next pre-planned set for you ([settings](https://www.fitnotesapp.com/settings/)).

**Reorder.** On the Home Screen you long-press an exercise to enter selection mode, then long-press its drag icon. In the drawer you press, hold and drag ([home_screen](https://www.fitnotesapp.com/home_screen/), [Play listing](https://play.google.com/store/apps/details?id=com.github.jamesgay.fitnotes&hl=en_US)). This is pain point 4.

**Other features.** The rest timer remembers the last duration, can be set per exercise, and has vibrate, sound and auto-start (starts on save, or on check when Mark Complete is on) ([workout_tools](https://www.fitnotesapp.com/workout_tools/)). Workout tools are a 1RM calculator, a set calculator (% of a max, rounded) and a configurable plate calculator. Supersets are colour groups that auto-jump to the next exercise, each with a "Jump Between Exercises" toggle ([release_1_21](http://www.fitnotesapp.com/release_1_21/)). Routines are made of Days with predefined or copy-previous sets ([routines](https://www.fitnotesapp.com/routines/)). There is a calendar with category dots and filters ([Play listing](https://play.google.com/store/apps/details?id=com.github.jamesgay.fitnotes&hl=en_US)). There are 13 graph types, trophies for PRs by rep count, a workout timer and workout comments ([progress_tracking](https://www.fitnotesapp.com/progress_tracking/), [home_screen](https://www.fitnotesapp.com/home_screen/)). Version 25 added a dark theme and Google One backup ([release_25](https://www.fitnotesapp.com/release_25/)).

**Complaints.** One Play review from 2026-08-30 sums them up: "Add an exercise, takes 4 presses to get back to your workout. Can't delete more than 1 set at a time, and have to confirm each one, no swipe actions. Copying previous workouts or setting up a routine is a mess. No built in way to do multiple sessions on same day." Another review says unweighted exercises get no PRs, warm-ups cannot be excluded from volume, and an exercise belongs to only one category ([Play listing](https://play.google.com/store/apps/details?id=com.github.jamesgay.fitnotes&hl=en_US)). [S2] collects further complaints: a dated UI, no sync, no RPE field, and rare updates. Users praise it for being free with no ads and no account, for simple and fast logging, and for data ownership [S2].

## Q3. Patterns in other trackers

Note on sources: I could not pull reddit threads directly. Reddit sentiment below comes from aggregator blogs, some written by competing apps ([Cora](https://www.corahealth.app/blog/best-workout-tracker-reddit)), so treat it as secondhand.

**Whole workout on one screen.** Strong lists every exercise in one scrolling workout. You reorder by dragging the exercise name, swipe a set to delete it, and tick a checkbox to complete it ([Strong help](https://help.strongapp.io/article/229-my-first-workout)). Hevy works the same way, with "+ Add Set" under each exercise and swipe-to-delete ([Hevy track](https://www.hevyapp.com/features/track-workouts/)). Liftosaur shows one exercise at a time and you swipe between them ([Liftosaur features](https://www.liftosaur.com/features)). JEFIT uses a log screen per exercise ([JEFIT FAQ](https://www.jefit.com/support/faq)). FitNotes, Liftosaur and JEFIT therefore use one exercise per screen, and Strong and Hevy put the whole workout on one screen. One screen fixes pain points 1 and 4 directly.

**"Previous" values.** Strong has a Previous column. Tapping it copies last time's values into the set ([Strong tutorial video](https://www.youtube.com/watch?v=iZoo4PkkJnQ)). Hevy shows a PREVIOUS column and lets you choose where it comes from: the last time you did the exercise anywhere, or the last time within the same routine. When you add an exercise you have done before, Hevy pre-fills its sets, weight and reps ([Hevy help](https://help.hevyapp.com/hc/en-us/articles/36011896355479-How-to-Use-Previous-Workout-Values-to-Improve-Performance-in-Hevy)). JEFIT pre-fills each set with what you did last time ([JEFIT log](https://www.jefit.com/features/log-track)).

**Completion and auto-advance.** Strong, Hevy, Liftosaur, JEFIT and Boostcamp all use a checkmark per set, which also starts the rest timer. StrongLifts logs a set with one tap on its circle, and each extra tap removes a rep ([StrongLifts](https://support.stronglifts.com/article/212-log-sets)). Hevy and FitNotes auto-advance only within supersets ([Hevy supersets](https://help.hevyapp.com/hc/en-us/articles/35650286563095-The-Complete-Guide-to-Supersets-and-Smart-Superset-Scrolling)). FitNotes 2 for iOS makes "go to the next exercise" a setting: Prompt, Always or (implied) Never ([getfitnotes](https://getfitnotes.com/docs/workout-sets.html)). In a one-screen layout, completion can simply highlight the next unchecked set, with no prompt at all (inferred).

**Bulk editing.** Motra offers "All Sets / This Set / Auto Update". Auto Update shifts every later unlogged set by the same delta and leaves logged sets alone ([Motra](https://help.motra.com/en/articles/11081434-updating-set-weight-reps-and-rest-time)). FitNotes 2 for iOS selects several sets with a two-finger swipe and updates them together ([getfitnotes](https://getfitnotes.com/docs/workout-sets.html)). Bevel users asked for "if I logged 75 on set 1, adjust sets 2 and 3 to 75" ([Bevel feedback](https://feedback.bevel.health/feature-requests/p/update-strength-template-based-on-previous-weights-reps)). A wger pull request adds "sticky set values" that pre-fill the next set from the last logged set ([wger PR 1290](https://github.com/wger-project/flutter/pull/1290)). StrongLifts and Boostcamp (Pro) raise the weight automatically on the next session after a successful one ([StrongLifts progression](https://support.stronglifts.com/article/71-progression), [Boostcamp](https://www.boostcamp.app/workout-tracker)). This is the direct fix for pain point 2.

**Number entry.** Strong uses its own numpad, with a plate-calculator button next to it ([video](https://www.youtube.com/watch?v=iZoo4PkkJnQ)). Liftosaur's +/- buttons "step through the weights your equipment can make" ([Liftosaur set types](https://www.liftosaur.com/features/set-types)). FitNotes has a weight increment per exercise ([workout_tracking](https://www.fitnotesapp.com/workout_tracking/)).

**Rest timer.** The timer auto-starts on completion in Strong (default 2:00, with separate warm-up and working durations per exercise), Hevy, JEFIT (adjust by 15 s while running, set 0 to disable), Boostcamp and LiftLog ([Strong](https://help.strongapp.io/article/231-rest-timer), [JEFIT](https://www.jefit.com/features/rest-timer), [Boostcamp](https://www.boostcamp.app/features/rest-timer), [LiftLog](https://liftlog.online/)). StrongLifts rests longer after a failed set and skips the rest between warm-ups and after an exercise's last set ([StrongLifts timer](https://support.stronglifts.com/article/39-timer)). Hevy does not start the timer before a drop set ([Hevy set types](https://help.hevyapp.com/hc/en-us/articles/34896293707927-Set-Types-in-Hevy-Explained-Drop-Sets-Warm-Up-Sets-and-More)). On Android, Boostcamp shows the countdown in an ongoing notification ([Boostcamp](https://www.boostcamp.app/features/rest-timer)).

**Reordering and supersets.** Strong uses drag on the exercise name. Hevy offers reorder through drag-and-drop from the exercise's menu ([Hevy options](https://www.hevyapp.com/features/exercise-programming-options/)). At the end of a routine workout, Hevy asks whether to "Update Routine" if the order or set count changed ([Hevy](https://help.hevyapp.com/hc/en-us/articles/38387296276375-Update-Routine-vs-Keep-Original-Routine)). Supersets are colour-coded groups in Hevy, FitNotes and JEFIT.

**Templates vs repeat last.** Strong limits free users to 3 routines and Hevy to 4 ([Strong App Store](https://apps.apple.com/nz/app/strong-workout-tracker-gym-log/id464254577), [Kinoku](https://kinoku.app/compare/best-free-workout-tracker-apps-android)). Boostcamp can turn any past workout into a template ([Boostcamp tips](https://www.boostcamp.app/blogs/tips-and-tricks-to-using-boostcamp-app)). FitNotes has both copying and routines.

**Set types and RPE.** Strong tags sets as Warm-up, Drop or Failure, and warm-ups are left out of charts. It also has a Pro warm-up calculator ([Strong set tags](https://help.strongapp.io/article/166-set-tags)). Hevy has the same tags, an optional RPE column (6 to 10), and a toggle for whether warm-ups count in stats ([Hevy settings](https://help.hevyapp.com/hc/en-us/articles/33882110558743-Workout-Settings-Preferences-Timer-Warm-up-calculator-Plate-Calculator-Smart-Superset-Scrolling)). Fitbod uses RIR to adjust its recommendations ([Fitbod](https://help.fitbod.me/hc/en-us/sections/360001078993-Understanding-Fitbod-How-It-Works)). FitNotes has none of these, and users work around it with separate "(Warm Up)" exercises [S5].

**PRs and charts.** JEFIT shows an estimated 1RM on each set and flags PRs live ([JEFIT log](https://www.jefit.com/features/log-track)). FitNotes has 13 graph types plus rep-max PRs ([progress_tracking](https://www.fitnotesapp.com/progress_tracking/)).

**Data ownership.** Hevy and Strong exports cannot be imported back into the same app ([Kinoku](https://kinoku.app/learn/move-workout-history-to-another-app)). Liftosaur's full JSON export round-trips, and its CSV imports show a preview first, then offer undo ([Liftosaur](https://www.liftosaur.com/features/import-export)). Badger takes a safety copy before every import ([Badger](https://badger.fit/guides/switching/)). Strong and Hevy require an account ([Kinoku](https://kinoku.app/compare/best-free-workout-tracker-apps-android)).

**Praise and complaints.** The most common reported complaint is "too many taps to log a set". Strong is seen as fastest, and Hevy as "heavier over time" ([Cora](https://www.corahealth.app/blog/best-workout-tracker-reddit), secondhand).

**Open source.** Flex (formerly Flexify) is Flutter, offline and MIT-licensed, with plans, rest timers and graphs ([GitHub](https://github.com/brandonp2412/Flexify)). Massive is archived in favour of Flex ([GitHub](https://github.com/brandonp2412/Massive)). LiftLog is React Native, local-only, logs a set with one tap and starts the timer automatically ([GitHub](https://github.com/LiamMorrow/LiftLog), [site](https://liftlog.online/)). The wger Flutter app talks to a server over REST ([GitHub](https://github.com/wger-project/flutter/)). Liftosaur is AGPL, works offline and progresses through scripts ([llms.txt](https://github.com/astashov/liftosaur/blob/master/llms.txt)).

### Ranking for this app

**Adopt**
1. One scrolling workout screen with a card per exercise, separated by a header and divider: fixes pain points 1 and 4, and it is what Strong and Hevy do.
2. Inline per-set rows (weight, reps, check) with a muted "last time" value beside each set: brings FitNotes' pre-fill and Hevy's PREVIOUS column into one row.
3. Checkmark per set that starts the rest timer and quietly focuses the next unchecked set, with no confirmation dialog: removes pain point 3.
4. Cascade edit: changing a set's weight or reps applies the change to the later unchecked sets of that exercise, plus an "all sets +/- increment" action on the card: fixes pain point 2, following Motra's Auto Update.
5. Copy a past workout or repeat the last one, copying sets as unchecked plans: matches how he already trains and FitNotes' own data model.
6. Drag handle on each card header, with cards collapsed during the drag: makes reorder one gesture, where FitNotes needs two long-presses.
7. Rest timer with a per-exercise default, an ongoing notification and vibration: every competitor has this, and Android needs a notification so it survives a locked screen.
8. Lossless `.fitnotes` import (categories, exercises, sets in `_id` order, comments, workout comments, routines, supersets), recomputing PRs: this is his history.
9. Own SQLite backup and CSV export: keeps the data ownership that FitNotes users value most.
10. Per-exercise increment and steppers next to a tappable number field: FitNotes already has these and he knows them.

**Consider later**
- Warm-up set tag excluded from PRs and volume: cheap, and FitNotes users ask for it.
- PR badge and estimated 1RM (Brzycki, matching FitNotes) on the exercise history screen: FitNotes parity for reviewing progress.
- Per-exercise history and a simple chart (e1RM, max weight, volume): useful, but not needed for logging.
- Supersets as groups: FitNotes data includes them, so import should keep them, but the UI can wait.
- Routines as named templates: copying a past workout covers most of the need for one lifter.
- Plate calculator: helpful for barbell lifts, but FitNotes users can live without it.
- Optional RPE/RIR field per set: low cost, but only valuable if he trains by RPE.

**Skip**
- Accounts, cloud sync, social feeds: single user, offline.
- Program scripting and auto-progression engines (Liftosaur, Fitbod, StrongLifts): heavy, and he plans his own workouts.
- Exercise library with videos: he already has his exercises from FitNotes.
- Drop/failure set types and a warm-up calculator: rarely needed, and they add UI weight.
- Watch apps and Health Connect: out of scope for a simple native logger.
